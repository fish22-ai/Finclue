> 对应需求中的【表 1 Career Intelligence 事实表】与【表 2 Career Insights 分析表】
> 类型编号为飞书 Bitable field type：1=多行文本 2=数字 3=单选 4=多选 5=日期 15=超链接
>
> 最后更新：2026-09-15（事实表精简 26 → 16）

## 表 1 · Career Intelligence（事实表）

**13 个可见列 + 3 个隐藏列。**

设计目标来自用户原话：「我每天看也就扫一眼」。所以可见列只留**一眼能判断"这条对我有没有用"**的信息。

### 可见列（13）

| # | 字段名 | 类型 | 说明 |
|---|---|---|---|
| 1 | date | 日期(5) | **抓取日期**（非发布时间），用于增量窗口 |
| 2 | company | 文本(1) | 机构名，保留原文写法 |
| 3 | institution_type | 单选(3) | 券商/投行/行研/PE/VC/公募/私募/资管/银行/信托/保险/量化/金科/财资/风控/财会/其他 |
| 4 | department | 文本(1) | 部门/组 |
| 5 | role | 文本(1) | 岗位名 |
| 6 | city | 文本(1) | 用文本：城市写法太杂（HK / Hong Kong / 香港 / 中环），单选会炸出上百选项 |
| 7 | salary | 文本(1) | 保留原文，不换算 |
| 8 | wlb | **文本(1)** | 一句人话。含工作时长、周末是否加班、强度感受 |
| 9 | **recruiting_bar** | 文本(1) | JD 书面门槛。含学历/专业/实习经历/证书要求 |
| 10 | **actual_bar** | 文本(1) | 真实录取门槛 —— 与 recruiting_bar 严格分开 |
| 11 | experience_summary | 文本(1) | 经历摘要。含面试轮次与内容、留用/转正情况 |
| 12 | source_url | 超链接(15) | **业务幂等键** |
| 13 | tags | 多选(4) | 自由生成，写入前自动补选项 |

### 隐藏列（3）—— 建议在飞书视图里隐藏

| 字段名 | 类型 | 为什么还留着 |
|---|---|---|
| published_at | 日期(5) | 面经过期很快。判断"这条还准不准"必需。日期已在 `date` 列可见，故可隐藏 |
| source_type | 单选(3) | 一手经历 / 求职博主 / 引流广告 —— **决定这条值不值得信** |
| evidence | 文本(1) | **「AI 禁止脑补」的审计依据**。JSON 字符串 `{字段名: 原文引用}`，砍了就再也追溯不了每个字段的出处 |

> **隐藏方式**：飞书表格视图 → 字段配置 → 取消勾选这三个字段。
> 数据仍在表里，API 仍可读写，只是不占屏。

## 相对初版的改动（2026-09-15）

### 合并（内容并入，不再单独成列）

| 原字段 | 并入 | 原因 |
|---|---|---|
| `working_hours` | `wlb` | 单列只有"9:30-21:00"这种碎片，并进 wlb 才读得懂 |
| `weekend_work` | `wlb` | 同上 |
| `education_requirement` | `recruiting_bar` | 本来就是 JD 门槛的子集 |
| `internship_requirement` | `recruiting_bar` | 同上 |
| `interview_rounds` | `experience_summary` | 轮次单独成列没意义，要连着内容看 |
| `interview_content` | `experience_summary` | 同上 |
| `return_offer` | `experience_summary` | 一行文字说清楚即可 |

> `wlb` 因此**从单选改为文本** —— 单选装不下"早9晚9、周末偶尔加班、项目期连轴转"。
> 飞书不支持改字段类型，实现上是删了重建。

### 删除

`source_account`、`salary_unit`、`confidence`

> ⚠️ **删 `confidence` 的连带影响**：洞察 prompt 原本按 `confidence` 做质量加权。
> 现已改为按 `source_type` 判断（`first_hand` > `career_account`/`community`，
> `marketing` 直接忽略）。

## 字段唯一真源

`src/schema.py` 是字段定义的**唯一真源**。改字段只改那里，然后跑：

```bash
python src/setup_feishu.py
```

脚本会按 schema 自动**补缺失字段、删多余字段**（幂等，可反复跑）。

## 写入前必须知道的事

1. 单选/多选字段的**选项**：单选必须预先建好；多选（`tags`）由 `writer.py` 写入前自动补
2. 日期字段传**毫秒时间戳**（int）
3. 超链接字段传 `{"link": ..., "text": ...}` 对象
4. **补选项时必须全量回传已有选项**，否则老选项被覆盖丢失
5. **必须读飞书表 live 字段类型**（`GET .../fields`），不能只信本地 schema
6. wiki 内嵌多维表：URL 里的 token 是 `wiki_token`，**不是 `app_token`**，需先经 wiki API 解析
7. 单批 50 条
8. 飞书 API 实测约 **1/5 概率 SSL 抖动**，客户端已加 5 次退避重试（累计约 45s）
